# BPM 사이트 구현 상태

**기준일:** 2026-10-28  
**기준:** 저장소에 존재하는 코드와 테스트·개발 스크립트. 운영 서버에서의 배포 완료 여부는 별도로 표시한다.

이 문서는 BPM 사이트에서 **현재 동작하는 것**, **코드는 있으나 운영 검증이 필요한 것**, **아직 없는 것**을 구분하는 기준 문서다. 제품 방향은 [`../PRODUCT.md`](../PRODUCT.md), 상세 설계와 결정 기록은 [`BPM_Backend_Plan.md`](./BPM_Backend_Plan.md)와 [`Replay_Viewer_Plan.md`](./Replay_Viewer_Plan.md)를 따른다. 개인정보 처리 준수 기능 9개 항목의 코드 기준 판정과 구현 순서는 [`Privacy_Compliance_Implementation_Plan.md`](./Privacy_Compliance_Implementation_Plan.md)에 기록한다. 계획 문서와 이 문서의 상태가 다르면 이 문서의 날짜가 더 최신인 항목을 현재 상태로 본다.

## 상태 정의

| 상태 | 뜻 |
|---|---|
| **구현됨** | 저장소에 사용자 경로와 서버 로직이 있으며 로컬 시험 근거가 있다. 운영 배포 완료를 뜻하지는 않는다. |
| **부분 구현** | 핵심 코드는 있으나 제품 문구, 배포, 외부 서비스 연결 또는 품질 검증이 남았다. |
| **미구현** | 사용자에게 제공할 기능이 아직 없다. |
| **보류** | 의도적으로 이번 출시 범위에서 제외했다. |

## 7. 운영 배포 상태

코드 구현과 서비스 공개 준비를 구분한다. 다음 항목은 저장소 코드만으로 완료를 증명할 수 없다.

- Railway의 Next.js·Postgres·Python worker와 Cloudflare R2를 실제 운영 값으로 연결한 첫 업로드
- Battle.net 운영 OAuth 로그인과 런처 기기 연결
- 업로드 → 분석 → 내 페이지 → C2 공개·통계 → 철회·삭제 → 계정 탈퇴 전 과정
- DB 백업·복구, R2 삭제 확인, 큐 길이·분석 지연·오류율·워커 상태 모니터링
- 버전이 있는 DB 마이그레이션 체계. 현재 DB 스키마는 애플리케이션 시작 시 보장하는 방식이다.
- 보안 헤더/CSP, 관리자 인증, 비밀값·rate limit의 운영 점검
- 업로더 Setup.exe와 HTTPS 업데이트 피드의 실제 배포

## 8. 다음 우선순위

1. [개인정보 처리 준수 기능 계획](./Privacy_Compliance_Implementation_Plan.md)의 P0 항목인 원본 파기, 보관기간 자동 파기, 신고 원자화와 단기 해시 TTL을 구현한다.
2. 개인정보 안내의 빈 운영 정보와 보관기간을 확정하고, 구현이 검증된 범위에서만 정식 정책 버전을 확정한다.
3. Railway·Postgres·R2·worker를 연결하고 운영 환경 종단 시험을 통과시킨다.
4. Battle.net 로그인부터 런처 연결·업로드·분석·철회·삭제까지 한 흐름으로 검증한다.
5. Setup.exe 설치와 HTTPS 자동 업데이트를 검증한 뒤 다운로드 경로를 연다.
6. 리플레이 분석 랜딩의 “준비 중”을 실제 공개 범위에 맞게 바꾸고 “실시간”을 “경기 후 자동 분석”으로 교정한다.
7. 홈·가이드·리플레이 분석·AI 순서로 실제 미디어 슬롯을 채운다.
8. AI 평가와 AI 통계는 사실 추출 파이프라인의 품질이 안정된 뒤 단계적으로 추가한다. C3는 실제 학습 전에 후보·반출·학습 이력을 먼저 구현한다.
9. Challenge S1은 로비 표식·점수·부정 방지·법적 운영이 모두 결정된 뒤 연다.

## 9. 검증 명령

웹 코드나 콘텐츠를 바꾼 뒤(`test:privacy`는 DB 열을 추가하거나 바꿀 때 [개인정보 데이터 목록](./Privacy_Data_Inventory.md)과 맞는지 확인합니다):

```powershell
npm run validate:data
npm run test:privacy
npm run test:report-atomic
npm run test:deletion
npm run typecheck
npm run lint
npm run build
```

개발 흐름 시험은 `scripts/dev/`의 account, match, public, upload, worker flow 스크립트를 사용한다. Python 워커는 `python -X utf8 -m unittest discover -s worker/tests`, 업로더는 `dotnet test uploader/tests/Bpm.Uploader.Tests/Bpm.Uploader.Tests.csproj -c Release`로 확인한다.
